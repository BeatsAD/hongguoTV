# 上游修复检测、保留定制与审核发布

本 fork：BeatsAD/hongguoTV；参考上游：N3urda/hongguoTV/main。定时任务运行在 GitHub，不依赖电脑或电视开机。

## 自动路径

1. 约每 6 小时检测固定上游 main；手动运行 upstream-sync.yml 可立即检测。
2. 仅对 .github/upstream-sync/policy.json 列出的 8 个核心协议/媒体文件逐文件三方合并。比较本机当前实现、该文件上次已接纳的上游版本及新上游版本，保留不重叠的本地修改。
3. 包名、签名、分发渠道、依赖配置、原生界面、资源、遥控交互、其他功能模块及现有测试均不自动同步。删除、二进制、两边独立新增和重叠修改作为待人工移植项，原文件保留。
4. 可兼容部分生成机器人署名 PR，包含来源、实际修改清单和未移植项。没有兼容源码时保持草稿，不能自动合并。每个核心版本只提一次；已有提案不被重复提交或覆盖，人工关闭的提案不会反复重建。
5. 自动明确 dispatch 候选分支的 tv-release.yml，只运行验证，不读取签名 Secrets 或发布。避免机器人创建 PR 后，GitHub 的工作流审批机制导致 CI 未执行。
6. 必需检查为 TV verification 与 Upstream preservation。前者跑项目完整检查、发布脚本和同步算法测试；后者使用 main 中的可信策略，重新核对三方合并结果和所有受保护文件，拒绝整文件覆盖、篡改状态或删除。
7. 由 BeatsAD 审核当前 PR 提交。新提交会使旧审核失效；机器人审批和其他提交的审批不算通过。main 开启分支保护，要求两项检查、1 个 CODEOWNER 审核、过期审核失效、对管理员同样生效，并禁止强推与删除。
8. 控制任务在 CI 完成后及约每 10 分钟核对审核状态。只合并已审核、检查成功且提交未变化的同步 PR，使用带 head SHA 的 GitHub 合并 API。也可由所有者审核后在 GitHub 手动合并。
9. 机器人合并不会可靠触发普通 push 工作流，所以合并后明确 dispatch main 的构建发布；同一 SHA 已有运行时不重复触发。发布失败可通过正常 Actions 重跑处理，不在后台反复创建新版本。
10. 发布任务再次核对 main 对应 PR 的审核以及是否存在应用源码变更，通过后才恢复签名材料、打包并公开更新。上传前再次复核审核；update.json 记录源码提交及审核 PR。纯配置、说明或同步水位变化不发布 APK。

GitHub cron 是尽力调度，可能延迟。公开仓库长期无活动可能被 GitHub 停用定时任务，届时需在 Actions 恢复；本流程未声称提供独立常驻监控服务。

## 部分同步与待移植项

state.json 按文件记录接纳水位，并保存 unresolved。初始水位来自两个仓库真实共同祖先 eea73e6；不把尚未移植的历史差异当作已修复。

一次 PR 可以只接纳不冲突的部分。冲突文件的水位保持旧值，未用上游内容覆盖；工作流报告列出其余界面、新功能、依赖和测试路径。合并这个 PR 不代表待移植问题已经解决，也不代表已经完成实体电视验收。

上游新增依赖、辅助类或修改 Android 代码时可能需要人工移植。现有测试会阻止不完整依赖直接发布。保留定制的语义还需人工审核，三方文本合并不等于行为完全相同。

## 单人仓库的人工移植

仓库所有者不能审核自己创建的 PR。人工开发时使用新的 codex/分支，提交并推送后，在 upstream-sync.yml 的手动运行表单中填写 source_branch；机器人会代为创建 PR 并明确触发测试，所有者便可审核。

人工分支不要使用保留的 codex/upstream-sync/ 自动命名空间。人工修改可增加回归测试或适配依赖，由所有者逐项核对界面和功能后合并。处理某个冲突文件后，只推进该文件的上游水位，勿把未移植项一起标成已完成。

## 配置和权限

- CODEOWNERS 指定 BeatsAD 为审核人。
- 控制工作流只用本仓库 GITHUB_TOKEN，无需上传个人 PAT 或新建 GitHub App。
- 仓库需允许 GitHub Actions 创建 PR。该仓库开关同时开放机器人提交 review 的 API，但本流程不调用审批 API，且发布门禁明确只认可 BeatsAD 对当前 SHA 的 APPROVED 审核。
- 检测/合并任务拥有本仓库 contents、pull-requests 和 actions 写权限；不执行候选代码、不接收签名密钥。
- 候选编译/测试只有读取权限，不接收签名密钥。签名任务仅在 main、所有检查及审核门禁通过后运行。
- 首次部署这些流程不改变电视包名或签名，不安装或清除任何设备数据。在线升级仍沿用 AUTO_UPDATES.md 的覆盖安装和数据保留规则。
